# BBC annunciator diagnostics planning

The owner proposed a live link through the annunciator, a disk-read cue when the link becomes available, fault/power diagnoses and actionable advice for bringing the machine to steady state, plus a non-pressable DIAGNOSTIC LINK pilot. They then explicitly requested further planning and a new prompt instead of implementation. Saved `doc/prompts/bbc-micro-annunciator-diagnostics.md` and linked it from the older workstation prompt. No live diagnostic adapter or pilot was implemented.

The prompt separates BBC power, boot, link availability, diagnostic loading and live updates; it uses the annunciator's actual incoming/station-battery source rather than making startup advice depend on an already running machine. It calls for dependency-ordered hints from real Level0 state, scene-specific coverage without changing Level2 narration, bounded disk activity/sound, and a completion report at `doc/reports/bbc-micro-annunciator-diagnostics.md`. The owner subsequently clarified that the pilot means diagnostics actually available, analogous to a completed serial handshake: both endpoints powered, the diagnostic application ready and a successful session/read. BBC power-off immediately extinguishes it; link/annunciator loss also clears it and shows NOT CONNECTED. The prompt now records that final clarification rather than the earlier power-only interpretation. The physical machine data cable remains deferred pending a separate interface choice. Startup uses `CHAIN "DIAG"`, checked against the BBC Micro User Guide.

The owner named the fourth pilot and its associated proprietary 1980s monitoring technology Neumann Link™. The prompt now uses that branding on the planned lamp and diagnostic program. It remains a planned handshake/availability indicator, not an implemented runtime feature.
