# Encabulator: agent guide

This file provides guidance to coding agents (Claude Code, Codex and others) working in this repository. `CLAUDE.md` is a symlink to it.

A browser game about a mysterious machine whose operation is stupid, opaque and profoundly unsafe, after the Rockwell Retro Encabulator film. The setting is an industrial plant in the United States in the late 1990s, and the game is in English. It follows the VX3 Simulator (`../vx3_simulator`), from which it took its controls and widgets, its effects, its world graph library and some of its sounds. Stack: Vite+ (`vp`: Vite, Vitest, Oxlint and Oxfmt in one toolchain, configured in `vite.config.ts`), TypeScript, Three.js, `@preact/signals-core`.

For now the game is a series of development rooms that test the concepts the machine will need; the machine itself, and the plant around it, are not built yet.

## Rules

- Work on `main`. Do not create branches or worktrees unless the owner asks.
- Before committing, run `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test` and `npm run build`. CI (`.github/workflows/ci.yml`) runs the same five, and on a push to `main` that passes them it deploys the build to GitHub Pages: https://trebizondoculpepper.github.io/encabulator/. Vite's `base: './'` keeps every asset path relative, so the site works under `/encabulator/`; keep links relative too (`?room=hall`, never `/?room=hall`).
- Markdown is one paragraph per line, never hard-wrapped.
- Record significant sessions in `diary/`.
- Never commit `agent-mailbox.toml` or `agent-inbox.toml`.
- Ask the owner one question at a time.
- Record every sound credit in `CREDITS.md` (author, source URL, licence, edits); technical notes go in `src/audio/assets/README.md`.
- Keep working recordings in `resources/sound/` (`effects/`, `narrations/`, `bgm/`); only prepared game assets belong in `src/audio/assets/`.
- Treat volumes named `NO NAME` as read-only sources; copy files into the workspace before editing them.

## Commands

- `npm run dev`: Vite dev server on `http://127.0.0.1:5174/` (strict port; the VX3 Simulator has 5173).
- `npx vp test run src/game/world/devices.test.ts`: one test file; add `-t "<name>"` for one test. Tests import from `vite-plus/test`, not `vitest`.
- `npm run format`: apply Oxfmt. `npm run check` runs formatting, linting and type checks together (`vp check`).
- Linting is Oxlint, type-aware, with the old ESLint rules carried over (`lint` in `vite.config.ts`); formatting is Oxfmt (`fmt`, single quotes, trailing commas, 80 columns).

## Rooms

`src/main.ts` opens a room from `?room=` and keeps rooms alive while another is shown. The rooms are not one connected world: each is separate, and a portal (a patch of wall in the colour of the room it leads to, named above) sends whoever walks into it, or clicks it from anywhere it can be seen, straight to that room, standing in front of its portal back (`src/game/dev-room-links.ts`, `src/scene/portals.ts`). `src/scene/portal-network.test.ts` checks that every portal in every room, and every door of the Hall's station, can be both walked into and clicked, and leads somewhere with a way back; add a room to `ROOMS` and it is tested too. The development rooms link to their neighbours and the Hall; the Hall's door station also leads to the Rhombus mini-game, whose exit returns to the Hall:

- **dev0, Controls and Displays** (`/?room=dev0`, the default; `src/rendering/controls-room.ts`). The kinds of controls, displays and working parts the machine will be built from, taken from the motor control centre in the Retro Encabulator film (see `doc/research/retro-encabulator.md`). On the north wall, the CONTROLS board (`createControlsBoard` in `src/rendering/test-boards.ts`) holds one of each 30 mm pilot device, and the DISPLAYS board (`createDisplaysBoard`) holds one of each indicator and display with test controls under it. Along the south wall, a pedestal for each working part of a motor control unit (`src/rendering/device-pedestals.ts`): the unit with its door, operating handle and breaker; a contactor; a thermal overload relay; a control fuse; a drive's power board with its bus capacitors; and an induction motor. Each pedestal has a sloping test panel that puts its part through what it does, failures included. `?view=controls`, `?view=displays` and `?view=pedestals` start in front of each. In development, `devControls.parts()` lists every clickable part, `devControls.work(name)` works one, `devControls.view(x, y, z, tx, ty, tz)` places the eye and `devControls.log()` reads the log.
- **dev1, Effects** (`/?room=dev1`, `src/rendering/effects-room.ts`): the VX3 Simulator's end-state effects room (colour channels, π drift, warp, sparks, smoke, embers), driven by `src/game/phase-effects.ts` and recorded with `src/game/effect-settings.ts`.
- **dev3, Racks** (`/?room=dev3`, `src/rendering/racks-room.ts`): the industrial design of 19-inch racks, built to catalogue dimensions (`doc/research/rack-dimensions.md`): a bayed suite of 42U server cabinets, an industrial enclosure on its plinth, a 24U cabinet on castors, an open two-post relay rack, a 12U cabinet and an open frame, each branded and filled with units of every kind, and loose units on display plinths with nameplates. It is only appearance; nothing works. `src/scene/rack-equipment.ts` builds the cabinets (`createRackCabinet`, `createCabinetSuite`, `createRelayRack`) and the units (`createRackUnit`: blank, vented, handles, door, drawer, fans, drives, patch, shelf of half-width units, controls, display). `?view=racks` and `?view=plinths` start in front of each.
- **dev6, Retro Encabulator MCC** (`?room=dev6`, `src/rendering/encabulator-room.ts`): a seven-section Allen-Bradley CENTERLINE-style motor-control lineup, assembled from openable MCC bucket doors and the existing industrial controls, device views and rack units (`src/scene/retro-encabulator-mcc.ts`). It uses 90-inch sections, six-inch wireways and 6.5-inch bucket increments. A wider PLC bay contains period 1771-style I/O and reused rack units; starters expose breakers, contactors, overloads, fuses and terminals. The development room links west to dev3 and to the Hall, and the Hall station has a door to it. `?view=lineup|controls|plc` supplies inspection starts.
- **dev7, Corridor** (`?room=dev7`, `src/rendering/corridor-room.ts`): a zig-zagging basement passage beneath the plant with branches to a locker room, service bay, plant room and lift lobby. The reference photographs are copied into `resources/reference/underground-corridors/`. `src/game/corridor-plan.ts` defines the connected walkable footprint and collision walls; `src/scene/underground-corridor.ts` models painted blockwork, concrete floors, fluorescent fixtures, overhead services, fire doors, signs and connected industrial spaces. The room links west to dev6 and to the Hall. `?view=entry|dogleg|junction|lockers|lift` supplies inspection starts.
- **The Hall** (`?room=hall`, `src/rendering/hall-room.ts`): the great enclosed hall the whole game takes place in, and the hub of the dev rooms. A 150 × 90 m brutalist American interior, stepped in section (`src/scene/industrial-hall.ts`): a 24 m nave under a coffered waffle slab with skylights, lit by tall vertical clerestory windows, between 10 m side halls under thick slabs on massive columns, with polished concrete underfoot, industrial pendant lamps on chains after Lamp Copper's Astra pendant (`src/scene/pendant-lamps.ts`, instanced), tall windows in the side walls' bays and the end walls, and overcast daylight under a haze. The Hall is drawn by Three's WebGPURenderer (WebGPU where the browser has it, WebGL 2 otherwise) through a node-based render pipeline (`src/rendering/node-pipeline.ts`): one scene pass writes colour, diffuse colour with metalness, normal with roughness, depth and motion; screen-space global illumination (SSGI) adds light bounced between surfaces and ambient occlusion; screen-space reflections (SSR) put the hall in the polished floor and every glossy surface; bloom makes only what is brighter than white glare; temporal anti-aliasing (TRAA) smooths edges and the effects' noise. `?stage=colour|gi|ao|lit|reflections|reflected` shows one stage alone. The building finishes are node materials (`MeshStandardNodeMaterial` with `triplanarTexture`); the Hall's materials must work under WebGPURenderer, so no `onBeforeCompile` shaders there. WebGPU allows only four render targets in a pass (32 bytes a pixel), so add data to the scene pass by packing it into an existing target's spare channel. A door station in the middle of the nave (`src/scene/door-station.ts`, after Monsters, Inc.) leads to every other room; every other room has a portal back to it. Round the edges stand ephemera built to standard sizes (`src/scene/warehouse-props.ts`): ISO containers, GMA pallets of cartons, 55-gallon drums, IBC totes, a forklift, janitorial gear, scissor and boom lifts, pallet racking, switchgear, a transformer, a compressor, a gas cage, a workshop bench, bollards, a rolling ladder, a dumpster, and drum and pedestal fans standing switched off. In the north side hall stands the facility administrators' office (`src/scene/plant-office.ts`): steel-stud and drywall partitions with interior window bands and mini-blinds, an open door under a FACILITY ADMINISTRATION sign, a suspended tile ceiling with troffers, and 1990s desks, CRTs, chairs and filing cabinets inside; beside it an amenity block (`src/scene/plant-amenities.ts`) of MEN and WOMEN restrooms (doors a click opens and shuts; inside, tiled, with stalls, urinals, sinks and mirrors), a janitor's closet, a first aid room, a drinking fountain and a time clock. A drivers' toilet, its door also openable, stands by the docks, a glazed security booth overlooks the east personnel door, and an emergency shower and eyewash stands by the chemical store. `doc/research/plant-code-1990s.md` lists what the 1990s codes (OSHA 1910, the regional building codes, NFPA, the ADA) require, and the hall now has it (`src/scene/code-compliance.ts`): extinguishers within 75 ft, exit doors in the side walls with EXIT signs, emergency lights, pull stations and horn-strobes, a battery charging station, a break room with lockers, flammables cabinets, an MSDS station, separate gas cages, a stair to the north balcony and a safety notice board; `devHall.stats()` reports a frame's draw calls, triangles and how much detail is culled. For speed, every static prop and set piece is merged into a few meshes per material in 3 m chunks (`src/scene/merge-static.ts`), the hall's instanced batches (structure, services, markings, lamps) are split into 15 m tiles so off-screen tiles are skipped (`buildTiled` in `src/scene/instancer.ts`), and `src/rendering/detail-culling.ts` hides anything too small to see at its distance and fine detail (chain links, lamp cages, duct seams, hangers, grilles) beyond 35–45 m. New props need nothing extra: they are merged and culled where they are placed; something a click works or that moves must be left out of the merge; the middle of the nave is kept clear for the game. Building services hang from the structure (`src/scene/hall-services.ts`): gas unit heaters, cable trays and exhaust fans. Floor markings (`src/scene/floor-markings.ts`) follow American plant practice: yellow lanes, walkways and cells with arrows and zebra crossings, white storage locations, yellow-and-black hazard stripes, red-and-white keep-clear areas and stencilled words. Both end walls are solid, each with a great door in the nave's end (`src/scene/hall-doors.ts`): the owner chose the yellow high-speed fabric door for the east end and the blue vertical lift fabric door for the west (`devHall.door(n, end)` tries the other styles). Beside each stands a personnel door, open on the white glare of the overcast day, under a lit EXIT sign. The east end also has a truck dock door with bumpers and leveller in each side hall. A physical console desk by the door station (`src/rendering/hall-console.ts`, built on `effects-console.ts`) sets each surface's FINISH, SHADE, ROUGH and METAL (`src/scene/hall-surfaces.ts`, mapped from world position so textures keep their scale), the floor's SHINE (reflections) and BOUNCE (global illumination), the lamps' and sky's LEVEL and KELVIN (`src/game/colour-temperature.ts`), the ambient occlusion, the bloom and the haze; it remembers them in the browser. Control panels are always physical objects in the game, never HTML overlays, unless the owner says otherwise. `devHall.set({...})` changes settings from the console.
- **Rhombus mini-game** (`?room=rhombus`, `src/rendering/plinth-room.ts`): a dark gallery, drawn like the Hall by WebGPURenderer and `src/rendering/node-pipeline.ts`, with three plinths at the corners of a 20 m triangle, about ten seconds' walk apart (`src/game/plinths.ts`, tested). Over each turns a monumental exhibit about a metre tall, in a material of its own (`src/scene/plinth-exhibits.ts`): a rhombic bipyramid of iridescent, dispersive glass round a beating magenta core; a gold double helix with glowing base pairs; and an obsidian sphere veined with molten light, tilted like a planet, its veins drawn from noise in its own frame so its turning shows. The exhibits alone reflect a studio environment; the room stays dark. Walk within 4 m (`REACH`) of a plinth and its spotlight comes up while the others dim; away from all three they stand at a low level, dark enough that arriving plainly lights one (the plinths' stone is lit by its spotlight alone; only the exhibits reflect the studio). Each plinth also has a quiet, other-worldly loop of its own, synthesised and placed where it stands, heard only within 9 m and unrelated to its shape on purpose (`src/audio/plinth-drones.ts`: a struck-glass shimmer at the rhombus, a sliding breath at the helix, a low beating throb at the sphere); a click or key press starts the sound. The tracker records every arrival with the plinth visited just before (`previous`), every one before that (`before`) and how many times this one has been visited (`visit`), and the room dispatches a `plinth-arrival` event with it: the hook for context-sensitive narration selected by `src/game/plinth-narration.ts` and played by `src/audio/plinth-narration.ts` (31 original recorded lines, two intro continuations and 16 additional shape remarks). `devPlinths.view(...)`, `active()`, `previous()` and `arrivals()` help in development; `?view=overview` stands at the south end. The mini-game has one exit: a green steel door with a lit EXIT sign on its east wall, leading to the Hall. Glowing yellow floor tape and arrows trace a route from the south approach around the plinths to that door, outside their 4 m activation zones; illuminated EXIT signs on poles mark the route and both turns. Dev3 links to dev6 and the Hall through its portals. The old `?room=dev5` URL remains an alias for `?room=rhombus`; `?room=dev4` remains an alias for the Hall.
- **dev2, Hallucinations** (`/?room=dev2`, `src/rendering/hallucination-room.ts`): peripheral apparitions (`src/game/hallucination.ts`), perceptual ghosting (`src/game/ghosting.ts`, `src/rendering/ghost-overlay.ts`) and geometric patterns (`src/game/patterns.ts`, `src/rendering/pattern-overlay.ts`).

## Architecture

- `src/game/` is pure logic with no DOM or Three.js, with its tests beside it (`*.test.ts`).
- **Components** (`src/game/world/components.ts`) are every part's behaviour, apart from any model of the machine: inputs (Power, Latch), one source of truth for state (a bound world value or its own), guarded operator actions, silent sets from the model, and named transition and state sounds. Operator controls: LED pushbutton, momentary, switch, selector, key-locked selector, operating handle, mushroom stop, push-to-test pilot light. **Self-acting** parts move by what flows through them and sound as they act, whatever moved them: contactor (pull-in, drop-out, welded contacts), thermal overload relay (trip class, RESET once cool, TEST), fuse (I²t, replace), electrolytic capacitor (bulge, vent, smoke, replace), and the hour meter. Use a component for everything a player can work or a failure can strike; failures of board-level parts (a blown capacitor) are components too.
- **Views** (`src/scene/`) only draw. `industrial-controls.ts`: 30 mm push buttons, mushroom head, lever and key selectors, potentiometer, pilot lamp, legend plates and nameplates. `industrial-displays.ts`: stack light, hour meter, message display, operator terminal, drive keypad. `industrial-devices.ts`: the motor control unit, contactor, overload relay, fuse holder, capacitor board and motor. The 1980s parts from the VX3 Simulator (`eighties-controls.ts`, `panel-switchgear.ts`, `panel-instruments.ts`) are kept and reused.
- `src/rendering/part-sound-hub.ts` registers each component with its view so the room plays its sounds where it is; `src/audio/control-sounds.ts` synthesises or plays each kind of click, clunk, trip, pop and bang, and `src/audio/part-loops.ts` holds state sounds (60 Hz mains hum, relay hold, motor hum).
- **The world graph** (`src/game/world/graph.ts`) is a directed graph of cached functions on signals: inputs, fixed parameters, states, derived values and outputs, with declared actions and processes, and `analyse()` to list dead controls and unseen values. The machine will be built on it.
- Every knob and rotary selector turns the same way: a click on its left half turns it anticlockwise (down), its right half clockwise (up), one detent per click (`knobDirection` in `src/scene/rotary-knob.ts`).
- `src/rendering/first-person.ts` walks, looks and zooms. The game aims for realism: the VX3's PS1 look is retired. `src/rendering/ps1-material.ts` keeps its old name but now only makes the realistic standard material for the WebGL rooms (dev0 to dev3), which are still to move to WebGPURenderer like the Hall.
- Mains is American: 60 Hz, 480 V three-phase power, 120 V control.
- Everything is in English: labels, legends, log lines and notes. Some text carried over from the VX3 Simulator may still be German; translate it when found.
